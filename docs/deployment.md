# راهنمای استقرار نسخه ۰٫۲ انتخاب‌یار

این بسته، سورس قابل ساخت Next.js، پنج JSON نسخه‌دار، منبع شغلی ثابت، دو migration، seed و راهنماها را دارد. نسخه فعلی مرحله ۵ است: آزمون، Matching، گزارش وب و تولید گزارش PDF فارسی. نتیجه با برچسب **اکتشافی و اعتبارسنجی‌نشده** نمایش داده می‌شود.

برای نصب و استقرار از Node.js نسخه ۲۲ استفاده کنید؛ نسخه آزموده‌شده در `package.json` ثبت شده است.

## اجرای بسته بدون اتصال ابری

در پوشه‌ای که `package.json` قرار دارد:

```bash
npm ci
npm run validate:data
npm run build
npm run start
```

سپس آدرس `http://localhost:3000` را باز کنید. بدون متغیرهای Supabase، برنامه مسیر پیش‌نمایش محلی را اجرا می‌کند؛ پاسخ‌ها و گزارش آن در همان تب مرورگر می‌مانند. این حالت ذخیره‌سازی چنددستگاهی یا دیتابیس واقعی ندارد.

## فعال کردن آزمون اصلی

1. یک پروژه جدید Supabase ایجاد کنید. در تنظیمات Auth، [Anonymous Sign-Ins](https://supabase.com/docs/guides/auth/auth-anonymous) را فعال کنید. کاربر ناشناس Auth در پایگاه داده نقش `authenticated` می‌گیرد و دسترسی او به پاسخ‌ها با RLS محدود شده است.
2. در SQL Editor همان پروژه، migrationهای قبلی را فقط در صورتی اجرا کنید که قبلاً اعمال نشده‌اند؛ سپس به‌ترتیب `supabase/migrations/202610040001_catalog_030_question_count.sql`، `supabase/migrations/202610040002_matching_v2_snapshot.sql` و در پایان `supabase/seed.sql` را اجرا کنید. seed نسخه جدید `0.3.0-pilot` را فعال می‌کند و نسخه‌های قبلی را تغییر نمی‌دهد. migration دوم تابع ثبت نتیجه را با روش وزن‌دار شخصیت و ارزش‌ها هماهنگ می‌کند.
3. سه متغیر زیر را در محیط استقرار تنظیم کنید. مقادیر نمونه در `.env.example` واقعی نیستند:

| نام | مقدار | محل استفاده |
| --- | --- | --- |
| `NEXT_PUBLIC_SUPABASE_URL` | Project URL | مرورگر و سرور |
| `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` | Publishable key همان پروژه | مرورگر و سرور |
| `SUPABASE_SERVICE_ROLE_KEY` | کلید server secret یا service role همان پروژه | **فقط سرور**، برای ثبت نتیجه |

کلید سوم را در فایل ارسالی، Git، چت یا متغیر `NEXT_PUBLIC_` قرار ندهید. [مستند امنیت Supabase](https://supabase.com/docs/guides/database/postgres/row-level-security) توضیح می‌دهد که این کلید RLS را دور می‌زند. برای اجرای محلی، مقادیر واقعی را در `.env.local` بگذارید؛ این فایل در `.gitignore` است و در ZIP قرار ندارد.

## استقرار در Vercel

پوشه استخراج‌شده را به عنوان پروژه Next.js به Vercel بدهید؛ می‌توانید آن را به مخزن Git متصل کنید یا پس از ورود به Vercel CLI از پوشه ریشه دستور `vercel` را اجرا کنید. [راهنمای رسمی Next.js در Vercel](https://vercel.com/docs/frameworks/full-stack/nextjs) تنظیم ویژه‌ای برای این ساختار نمی‌خواهد. **هر سه متغیر محیطی را پیش از build/deploy اصلی در تنظیمات پروژه وارد کنید.** اگر بعداً متغیر عمومی را تغییر دادید، یک استقرار تازه بسازید تا نسخه مرورگر نیز مقدار جدید را بگیرد.

فرمان نصب از lockfile، `npm ci`، و فرمان ساخت، `npm run build` است. Framework preset را Next.js و root directory را پوشه `package.json` انتخاب کنید. `output: export` یا استقرار فقط استاتیک مناسب نیست؛ مسیرهای خصوصی و محاسبه نتیجه روی سرور اجرا می‌شوند.

## بررسی پس از اتصال

با دو مرورگر یا دو نشست جداگانه، یک آزمون تجربی و یک آزمون ریاضی بسازید. پاسخ‌ها را ذخیره، صفحه را تازه‌سازی، ۷۰ پاسخ را ثبت، نتیجه را محاسبه و گزارش تفصیلی را باز کنید. سپس دکمه «دانلود گزارش PDF» را بزنید و راست‌چین بودن، فونت فارسی، صفحه‌بندی و تطابق نمره‌ها با گزارش وب را بررسی کنید. بررسی کنید نشست دوم به آزمون اول دسترسی ندارد. با یک آزمون تازه که همه پاسخ‌های رغبت آن یکسان‌اند، باید گزارش بدون پیشنهاد رتبه‌دار نشان داده شود.

ساخت، TypeScript، ۲۳ آزمون و مرورگر محلی این بسته بررسی شده‌اند. اتصال HTTP به Supabase میزبانی‌شده هنوز آزمایش نشده، چون پروژه‌ای در اختیار نیست. پیش از دسترسی عمومی، بررسی دسترسی و عملکرد بالا باید در محیط Supabase واقعی انجام شود. شواهد علمی مورد نیاز برای ادعای اتکاپذیری آزمون در [پروتکل اعتبارسنجی](validation-protocol.md) آمده‌اند.
